# File Extensions and Common Development Files

## C

- **`.cc-writes`**  
  Not a standard general-purpose file extension. It may be a tool-specific file or marker. Its exact purpose depends on the application or development environment that created it.

- **`.csv` – Comma-Separated Values**  
  A text format used to store tabular data. Commonly used in data analysis, machine learning, and data exchange.

## D

- **`.dockerignore`**  
  Specifies which files and directories Docker should exclude when building an image.

- **`Dockerfile`**  
  Contains instructions describing how a Docker image should be built.

## E

- **`.env`**  
  Stores environment variables such as configuration values, API keys, and database credentials. Files containing secrets should normally not be committed to Git.

- **`.env.example`**  
  An example environment file showing which environment variables the project requires without containing real secrets.

## G

- **`.gitignore`**  
  Specifies files and directories that Git should not track.

## H

- **`.html` – HyperText Markup Language**  
  Used to define the structure and content of web pages.

## I

- **`.ipynb` – Jupyter Notebook**  
  A notebook file that can contain executable code, Markdown documentation, equations, tables, and visualizations. Commonly used for data analysis, machine learning, experiments, and education.

## J

- **`.js` – JavaScript**  
  Contains JavaScript source code, commonly used in web development.

- **`.json` – JavaScript Object Notation**  
  A text-based format for structured data. Commonly used for API responses, configuration, and data exchange.

## L

- **`.lock`**  
  A lock file that records exact dependency versions so that the same versions can be installed in different environments.

## M

- **`.md` – Markdown**  
  A text file using Markdown syntax for formatting. Commonly used for project documentation.

## P

- **`.py` – Python**  
  Contains Python source code.

- **`.py:64`**  
  Usually not a file extension. `main.py:64`, for example, commonly means line 64 of the file `main.py`.

- **`.pyc`**  
  Compiled Python bytecode generated automatically by Python. These files are commonly stored inside `__pycache__` directories.

## S

- **`.sh` – Shell Script**  
  Contains commands that can be executed by a shell, commonly in Linux environments.

- **`.sql` – Structured Query Language**  
  Contains SQL statements used to query or modify databases.

## T

- **`.toml` – Tom's Obvious Minimal Language**  
  A configuration file format. Python projects commonly use it in files such as `pyproject.toml`.

- **`.ts` – TypeScript**  
  Contains TypeScript source code. TypeScript extends JavaScript with features such as static typing.

- **`.txt` – Text File**  
  A general-purpose plain-text file.

## Y

- **`.yaml` / `.yml` – YAML**  
  A human-readable format for configuration and structured data. Commonly used for Docker Compose, CI/CD workflows, and application configuration.

# Common Development Files

- **`README.md`**  
  The main documentation file for a project. It commonly explains what the project does, how to install it, and how to use it.

- **`pyproject.toml`**  
  A central configuration file for modern Python projects. It can define project metadata, dependencies, build configuration, and development tools.

- **`poetry.lock`**  
  Generated by Poetry and records the exact versions of Python dependencies used by the project.

- **`requirements.txt`**  
  A commonly used file containing Python dependencies that should be installed for a project.

- **`docker-compose.yml` / `compose.yaml`**  
  Defines how multiple Docker services should be configured and run together.

- **`Dockerfile`**  
  Defines the steps used to build a Docker image.

- **`.gitignore`**  
  Defines files and directories that Git should ignore.

- **`.dockerignore`**  
  Defines files and directories Docker should exclude when building an image.

- **`.env`**  
  Stores environment variables and is commonly used for local configuration and secrets.

- **`.env.example`**  
  Documents the environment variables required by a project without containing real credentials or secrets.
